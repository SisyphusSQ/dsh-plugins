# Codex Home bridge

## Agreed scope

A read-only external plugin for DSH 0.2.1-rc.2 (migrated from 0.2.0-rc.2; see [dsh-0.2.1-migration.md](dsh-0.2.1-migration.md)). Input is CODEX_HOME (default ~/.codex), not workspace configuration. No model-login or unrelated credentials, sessions, history, state databases, remote downloads or writes into Codex Home. The user's latest direction supersedes Codex OAuth reuse and private authentication adapters: use DSH's own authentication system. Import only credential-free MCP configuration through the native DSH client; configure authenticated servers independently in DSH. Do not read Codex grants, use Keychain, implement a second store or initiate login/refresh. Skills and Plugins are whole-category switches; there are no item toggles. Plugin-owned skills follow Plugins, standalone Home skills follow Skills. Agents and global AGENTS instructions have separate switches. Connecting MCP and executing hooks require separate category-wide grants, disabled by default.

Settings are persisted through DSH's settings/profile mechanism. Disabling a category must stop discovery and retract registrations/connections; already consumed context cannot be erased. Source inspection and activation status must remain distinguishable. The settings UI exposes only aggregate switches and read-only diagnostics.

## Architecture

One external package, dsh-codex-bridge, with a host entry and optional browser entry. Parsing is local; catalog transport validation shares the native DSH configuration mapper. The host registers a lazy skill provider, message-context bridge, role delegation integration, and explicitly authorized execution adapters through public extension points. Every registration and process is lifecycle-owned. No new shared/core package.

Home metadata is accessed through targeted paths and a bounded reader with realpath containment and credential/state filename denial. A manifest may supply additional component paths only inside its own plugin root. This is not a general-purpose filesystem sandbox. Final-component symlinks are rejected by O_NOFOLLOW and canonical containment is checked, but portable Node path opens do not pin every ancestor directory: concurrent adversarial ancestor-symlink replacement between checking and opening is not fully prevented. Treat the selected Home tree as locally trusted while scanning; no claim of race-proof isolation is made. Config is projected to relevant keys and never sent wholesale to the browser/model. Credential-bearing MCP properties are redacted in diagnostics and blocked before execution. Explicit env/header fields are also blocked regardless of their names, rather than guessing which values are secrets. Plugin paths must stay inside the plugin root. Explicit missing/malformed files are diagnosed, never treated as an empty success. Secret/helper references are capability failures, not invitation to search credential files.

Portable plugin.json is canonical. The OpenAI extension replaces the compatibility overlay when present. Parse defaults, explicit path replacement and inline component definitions. Cache inventory is not an effective enablement oracle; conflicting versions and uncertain enablement remain diagnostic rather than guessed. Only Home-scoped state is in scope; cloud/workspace config compatibility cannot be inferred from Home alone.

Original skill identities and stable collision-resistant DSH names are both retained. Known namespaced invocation references are translated in memory, never in source files. Implicit invocation policy and resources remain intact. Skill dependencies are explicit diagnostics and must be accounted for before claiming executability.

Global AGENTS.override.md / AGENTS.md select the first nonempty file, with the configured byte limit. Inject as user-level instruction context, never system instructions. Project instructions remain DSH-owned because the user requested Home-only discovery.

Codex TOML Agent definitions need real delegation, not merely an inert preset. No imported agent may increase parent permissions. Models require an existing DSH provider mapping. MCP and hooks must not start while listing or registering a preset. Events not faithfully representable through the target host must be recorded as compatibility gaps, not silently mapped to a different event.

The dependency is now explicit; no install scripts ran. Native transport registration/tool ownership integration remains separate work.
- The owned transport combines SDK/caller cancellation with its own abort controller. Closing aborts active HTTP operations and blocks later credential lookups; SSE reconnection retries are disabled. It forwards the SDK's public protocol-version/session/per-request-stream contract. It supplies no auth provider, so there is no discovery, browser authorization or refresh side effect. The caller must close it on category/grant revocation.
- A regression test demonstrated that the SDK embeds raw HTTP failure bodies in rejected errors (`SdkHttpError`), which could expose a reflected bearer. The owned boundary now sanitizes both rejected operations and the error callback, retaining no raw error/cause. This is not a policy to suppress failures: operations still reject and callbacks still report generic failure.
- Two new transport tests first failed because the transport was absent; the reflected-body test failed against its initial implementation and passed after the correction. Host compilation and the transport/HTTP targeted run pass 10/10 without skips. A real SDK Client performs initialize, initialized notification and tools/list against an injected HTTP fixture; another test proves active request cancellation and no lookup after close. This is SDK protocol composition with test markers, not a real network request, DSH tool registry composition, Desktop deployment or authenticated Linear/Notion proof. The future production network boundary must honor host egress policy; previously denied DNS results must not be bypassed through this adapter.
- OAuth/token acquisition, secure at-rest backend selection, authenticated settings actions, native lifecycle mounting, category/grant revocation wiring and live read-only connectivity remain outstanding. No real credential file was read/written and Codex Home is unchanged.

### Revocable SDK connection ownership (round twenty-seven)

- `src/oauth-connection.ts` owns the real SDK Client and authenticated transport before awaiting initialization. Concurrent starts share one handshake; startup has a 60-second timeout. Closing aborts the transport immediately, including while initialization is pending, and closes the SDK client. Failed/closed instances are terminal and never automatically reconnect.
- Tool discovery checks authorization before startup and after its response, refuses results after close/revocation, and uses a 60-second SDK request timeout. SDK RPC failures are sanitized separately from transport errors, since server-controlled JSON-RPC error messages can also reflect secrets. No logger receives raw SDK errors.

### 历史通用鉴权状态（2026-10-07；已被 DSH 原生方案替代）

- **原生契约已证实**：隔离的 Codex 0.160.1 CLI、显式 file 后端和本机假 OAuth 服务完成受控登录对照。记录采用 `server_name|16hex` 键，服务名及原始 URL 绑定，`expires_at` 为绝对 Unix 毫秒；原生记录没有额外 resource 字段。改变服务名产生另一记录，Header/resource 配置变化不改变观察到的键；受保护资源元数据不匹配被原生 CLI 拒绝。只使用临时 Home 和假令牌，没有读取真实 store、Keychain 或登录凭据。

- **定向 file OAuth 已接线**：仅明确 file 后端、Home 原始服务身份、没有显式 Authorization 的连接可选择现存 grant。独立读取能力限制文件大小、普通文件、最终组件无符号链接，并在异步边界复核授权；只返回匹配且未过期的 access token 与 expiry。选择 grant 后每次请求重读；删除、过期、歧义或无效状态均拒绝，不刷新、不写 Home、不匿名降级。`oauth_resource` 是需求提示，不虚构存储中不存在的资源绑定。

- **本轮已完成的验证**：19 项定向测试全部通过、无跳过，包括真实 rc.2 Loader 主入口、假 file OAuth 与静态 Header 的本机 HTTP 执行、实际 SDK stdio 进程、modern/legacy 协商、工具策略、撤销、晚到发现及 effect 释放。Loader 的 schema/wire/result 快照经审阅；过期和移除假 grant 后没有额外工具 HTTP 调用，也没有匿名请求。假 Home 在外部回读保持原字节，测试有意变更的 grant 在测试后还原。这不是真实厂商、模型或 Web E2E。

### 当前 DSH 原生鉴权方案（2026-10-07）

- **用户决策**：停止 Codex 凭据复用和第二套鉴权实现，改用 DSH 自己的体系。此前 OAuth/Keychain 探测和私有 SDK 适配器记录仅保留为历史，不代表当前包能力。
- **当前接线**：全部导入连接仅通过公开 `@deepseek-ai/dsh-mcp-client@0.2.0-rc.2`。保留 stdio/Streamable HTTP、稳定命名空间、`${CODEX_PLUGIN_ROOT}`、调用超时及生命周期撤销。明确 transport type 必须匹配配置，未知字段不能静默丢弃。
- **凭据边界**：普通 HomeReader 继续拒读凭据；删除定向 file OAuth 读取、Keychain 探测、私有 SDK transport/tool owner、独立 grant store 及对应测试/辅助脚本和直接依赖。含 Header、显式 env、OAuth 或 credential 配置的条目在连接前 blocked，不读取值、不忽略字段后匿名连接；在 DSH 中独立配置该服务。未标注鉴权的普通 URL 按原生客户端契约连接，不查询 Codex store；401 不触发桥接登录或刷新。命令/参数和目标 URL 来自选定的可信本机 Home，不声称识别任意位置的内嵌秘密，亦不为本地可执行程序提供沙箱。
- **原生能力限制**：rc.2 公开 MCP 配置支持静态 Header/stdio env，没有公开 OAuth provider、fetch 注入或登录/刷新接口。此次简化不实现新的 OAuth 流程，也不能宣称所有厂商 OAuth 已兼容。独立 DSH 配置的存储、日志、凭据保护和传输策略归 DSH 管理，不沿用已删除私有适配器的重定向/错误净化保证。
- **撤销边界**：桥接的 ToolRuntime guard 在调用前拒绝已关闭分类的新工具调用；轮询后原生连接清理其工具及资源。它不复核已启动请求的返回授权，也不为原生资源请求添加独立 guard；在途结果和清理前的资源访问遵循 DSH 原生契约，不沿用历史私有 owner 的即时取消/丢弃输出保证。
- **状态语义**：MCP catalog 的 `connecting`/`connected`/`failed` 记录原生 fiber 的启动结果，不是持续的连接健康探测；启动后断连不会自动改写 `connected`，实际调用仍按原生客户端返回失败。当前关闭自动重连，不添加非公开状态监听；需要重新建立连接时关闭再开启导入分类或重新加载插件。
- **包验证**：原生方案 tarball 审计通过（76 项文件，运行时导入、导出与文档链接），解包产物的 2 项实际 rc.2 Loader 测试通过；消费依赖链接到精确 workspace cohort，不是安装到 profile 或真实产品 E2E。

- **验证入口**：实际 rc.2 Loader 同时挂载无鉴权导入和独立 DSH Header 鉴权连接。假 Codex grant 被忽略，鉴权导入没有请求，schema/wire/result 快照固定原生契约；关闭/卸载桥接不撤销独立 DSH 连接。已有 stdio/HTTP、撤销/启动竞争和 bounded-reader 回归继续验证。
